# Friends Premier League (FPL) Tournament Management System
## Final System Specification Document
### Version 1.0 (Leadership Approval Draft)

---

# Project Objective

Develop a lightweight automated tournament management web application for the Friends Premier League (FPL).

The system will automate:

- Match result handling
- Table calculations
- Qualification logic
- Tournament progression
- Knockout generation
- Standings updates
- Fixture generation

The primary goal is to eliminate manual spreadsheet management and create a professional tournament experience similar to real esports/sports tournament systems.

---

# Core Tournament Structure

# Total Teams

- 9 Teams

---

# Group Structure

Teams are divided into 3 groups.

| Group | Teams |
|---|---|
| Group A | 3 Teams |
| Group B | 3 Teams |
| Group C | 3 Teams |

---

# Stage 1 — Round Qualifiers

## Format

Each group follows a round robin format.

Every team plays:
- 2 Matches

---

# Matches Per Group

Each group contains:

1. Team 1 vs Team 2
2. Team 2 vs Team 3
3. Team 1 vs Team 3

Total:
- 3 Matches per Group

---

# Total Round Qualifier Matches

- 9 Matches Total

---

# Qualification Rules

## Qualified Teams

Top 2 teams from each group qualify.

Qualified:
- A1
- A2
- B1
- B2
- C1
- C2

Total Qualified:
- 6 Teams

---

## Eliminated Teams

Bottom team from each group gets eliminated.

Eliminated:
- A3
- B3
- C3

---

# Stage Locking Logic

The Main Qualifiers stage remains LOCKED until:
- All 9 Round Qualifier matches are completed

After completion, the system automatically:
- Calculates standings
- Determines qualified teams
- Eliminates bottom teams
- Generates Main Qualifier fixtures

No manual qualification selection required.

---

# Stage 2 — Main Qualifiers

## Match Structure

| Match |
|---|
| A1 vs B2 |
| B1 vs C2 |
| C1 vs A2 |

Total:
- 3 Matches

---

# Main Qualifier Advancement Rules

## Automatic Qualification

The winners of all 3 matches automatically qualify.

---

## Wildcard Qualification

Among the 3 losing teams, the BEST losing team also qualifies.

This creates:
- 4 Total Semi Finalists

---

# Wildcard Selection Priority

The wildcard team is selected using:

1. Goal Difference (GD)
2. Goals Scored

Additional tie-breakers may be added later if required.

---

# Stage Locking Logic

Semi Finals remain LOCKED until:
- All 3 Main Qualifier matches are completed

The system automatically:
- Determines winners
- Determines wildcard qualifier
- Generates semifinal fixtures

---

# Stage 3 — Semi Finals

## Teams

- 4 Teams

---

# Semi Final Fixture Generation

Semi final fixtures are automatically generated by the system.

Final pairing logic can be adjusted later if required.

---

# Stage 4 — Final

The winners of the Semi Finals automatically qualify for the Final.

The system generates:
- Final Fixture
- Champion Result

---

# Champion System

After the Final:
- The winning team is automatically marked as Tournament Champion.

---

# Table Structure System

The tournament uses TWO table systems.

---

# 1. Group Tables

Used during:
- Round Qualifiers

Purpose:
- Determine qualification within each group

Each group contains:
- Group A Table
- Group B Table
- Group C Table

---

# Group Table Sorting Rules

1. Points
2. Goal Difference (GD)

---

# Example Group Table

| Team | P | W | D | L | GF | GA | GD | Pts |
|---|---|---|---|---|---|---|---|---|
| Team A | 2 | 2 | 0 | 0 | 5 | 1 | +4 | 6 |
| Team B | 2 | 1 | 0 | 1 | 3 | 3 | 0 | 3 |
| Team C | 2 | 0 | 0 | 2 | 1 | 5 | -4 | 0 |

Top 2 teams qualify.

---

# 2. Overall Tournament Table

Tracks cumulative performance across the entire tournament.

Purpose:
- Tournament-wide rankings
- Wildcard comparison
- Statistics tracking
- Better presentation

---

# Overall Table Includes

- Matches Played
- Wins
- Draws
- Losses
- Goals For (GF)
- Goals Against (GA)
- Goal Difference (GD)
- Points
- Red Cards

---

# Overall Table Usage

The Overall Table is used for:
- Wildcard qualification comparison
- Tournament rankings
- Public statistics display

---

# Important Table Logic

Group qualification is determined ONLY using Group Tables.

The Overall Table does NOT affect:
- Group qualification positions
- Group rankings

It is used only for:
- Tournament-wide rankings
- Statistics
- Wildcard comparison

# Match Result Logic

# Points System

| Result | Points |
|---|---|
| Win | +3 |
| Draw | +1 |
| Loss | +0 |

---

# Red Card Penalty

If a team receives a red card:

- 1 point deduction applied

Example:
- Win = +3
- Red Card = -1
- Final Points = +2

---

# Goal Difference Logic

Goal Difference (GD) is automatically calculated.

Formula:

```text
GD = Goals For - Goals Against
```

The system should NOT manually store standings permanently.

# Database-First Development Approach

Development will follow a database-first architecture.

Correct workflow:

1. Finalize database schema
2. Create Supabase tables
3. Add relationships and constraints
4. Seed initial tournament data
5. Build frontend around the database structure

This avoids:
- backend rewrites
- inconsistent logic
- poor relational design
